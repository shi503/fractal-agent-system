## Context

What does a brand-new user hear from TaskFlow before they touch any setting? The research (`wiki/sources/notification-user-research.md`, n=6 self-hosting teams) turned this from a settings question into a positioning question: users do not tune volume gradually, they flip between everything-on and everything-off, and the flip is triggered by one bad experience in either direction.

## Answer

**TN-R 2026-08-09, ratified AR-A same day — locked.** The default posture is quiet, with a daily digest as the primary reading surface.

Concretely, for a user with no stored preference row:

| Category | Default state | Default cadence |
|---|---|---|
| Assigned to me | on | immediate |
| Direct reply | on | immediate |
| Card I own blocked | on | daily digest |
| Due date changed | on | daily digest |
| Watched board activity | off | daily digest |
| Self-caused events | suppressed, not overridable | — |

Two categories interrupt. Three roll into the digest. One is off. Self-caused events are suppressed unconditionally and are not exposed as a preference at all — 6/6 participants raised this unprompted, and exposing it as a toggle invites a user to enable it, hate it, and blame the defaults.

## Implementation constraint

No preference row is written on first render. A user with no stored preferences renders the default table above; only an explicit toggle persists anything. This keeps "reset to defaults" a delete rather than a migration, and lets a later change to the default table reach everyone who never touched their settings.

## Impact

- Scopes WS-3 (PreferenceCenter) and its acceptance criteria.
- The digest surface becomes the primary accessibility audit target in WS-8.
